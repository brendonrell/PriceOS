# Rarity Labs

Rarity on PD is **computed, not claimed**. Every project's census — artist traits, Fate, color — is derived deterministically from the same seeds every viewer's browser holds, so every number below is identical for everyone, needs no rarity API, and can be re-derived by anyone at any time.

**How:** Open any Output's character sheet — ❖ PD Rarity leads it; the full Pop Table is on the project's + More.

## PD Rarity — the headline

Every Output's character sheet leads with **❖ PD Rarity**: provable art-rarity (trait / Fate / color) folded with genome isolation into one 0–100 read. Underneath it, the piece's standing across the whole minted edition:

- **#3 rarest of 105** — the piece's rank across everything minted so far.
- **NONE HIGHER** — what rank #1 says instead of a number. The top of the edition, stated plainly.
- **POP n** — the piece's smallest club: the count of the rarest population it belongs to on any axis. POP 1 means it's the only one.

## The Pop Table

Every project page carries the full **Pop Table** (+ More): every axis of the census, every value with its edition count and share, sorted rarest-first. It's the whole population laid open — the table a rarity claim would have to survive.

## Where else the lab reaches

- **Trait pills** show each value's count and share in place.
- **Fingerprint bands** carry percentile tags — where the piece sits against its edition on every measured reading.
- **Closest Sibling (≍)** names the one piece in the edition most like this one, and on how many axes they agree.

Because the census recomputes as an edition mints, rarity on PD is a **living number**: a POP 1 today can become a POP 2 tomorrow. That's not a bug in the system — that's the honest answer.
